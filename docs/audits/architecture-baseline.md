# Architecture baseline

Baseline revision `98db16dcb4ae0b4b6f08e29f0b3682677a3115bf` on `main`, November 19, 2026. This file lists only the gaps that are still open in the current code. Gaps closed by Execution v2, the Local Fast Path and release 1.3.0 are removed.

Lydia Hallie's talk motivates delegating approvals to native policy, isolation to the environment, and completion checks to tests and CI. [Rethinking Claude Code Best Practices](https://ai.engineer/talks/vlfCjWuv4es-rethinking-claude-code-best-practices)

## Open gaps

| Capability | Finding | Still open | Evidence in current code |
| --- | --- | --- | --- |
| Routing and contract | PARTIALLY IMPLEMENTED | A task contract and the Local Fast Path skip the router. A plain legacy task still costs a router model call, and the Codex and Claude route schemas still differ. | `scripts/codex-run.mjs` (`ask('route', …)` when there is no contract), `workflows/ladder.js` route schema, `scripts/fast-path.mjs` |
| Verification | PARTIALLY IMPLEMENTED | Claude still has a model verifier judge the work, but finish now also runs `plan.verify` itself before applying and records its exit code, duration and 4 KiB output tails in history (`sandbox: HOST_UNSANDBOXED`, so the command is not sandboxed and criteria-only plans record null). | `workflows/ladder.js` (candidate snapshot before and after the verifier), `scripts/finish.mjs` (host command exit evidence, tree recheck after the command) |
| Failure and retry | PARTIALLY IMPLEMENTED | Legacy ladder runs (`scripts/codex-run.mjs` and `workflows/ladder.js`) now stop before the LLM diagnosis when a failure has the same candidate tree and the same reason as the previous one, through the shared `repeatsFailure` helper. A different failure is still diagnosed. Both paths now classify the failure reason into `attempt.failure` through the shared `failureKindOf` helper before diagnosis, and a `CONTEXT_LIMIT` failure stops without diagnosis, as in contract runs. Contract runs also classify error codes and stop on a repeat. Still open: the legacy repeat check compares only the previous attempt. | `scripts/codex-run.mjs` (`ask('diagnose', …)`), `workflows/ladder.js`, `scripts/ladder-rules.mjs` (`repeatsFailure`, `failureKindOf`), `scripts/task-contract.mjs` (`failureKind`) |
| Concurrency | PARTIALLY IMPLEMENTED | A claim coordinates legacy runs but does not constrain writes. Legacy Claude finish and contract runs reject changes outside the claimed scope; so does the fast path. | `scripts/runs.mjs`, `scripts/finish.mjs` (scope check), `scripts/codex-run.mjs` (contract scope check) |
| Security | PARTIALLY IMPLEMENTED | The default verification command runs in the host shell and records `HOST_UNSANDBOXED`. The Claude edit hook covers only its matched tools and fails open on errors. | `scripts/codex-run.mjs` (`command.sandbox = 'HOST_UNSANDBOXED'`), `hooks/guard.mjs`, `hooks/hooks.json` |
| Usage guards and handoff | PARTIALLY IMPLEMENTED | The panel file `.model-ladder/live.json` and `.model-ladder/HANDOFF.md` are single shared files, so the latest writer wins. Handoff reads per-run live state, refuses state from another run, and also writes a per-run copy `.model-ladder/runs/<runId>.HANDOFF.md` (the returned path), so two runs keep their own handoffs; the shared files remain latest-writer only. | `scripts/codex-run.mjs` (writes both live files), `scripts/codex-handoff.mjs` |
| History and telemetry | PARTIALLY IMPLEMENTED | Codex usage is summed from every streamed `turn.completed` event, not the bounded stdout tail (128 KiB). Raw event and stderr files stay in each run directory and can contain sensitive data. | `scripts/codex-exec.mjs` (`onStdout` usage accumulation, `*.events.jsonl`) |
| Configuration | CONFIRMED | Project-provided verification commands and policy have the same trust as personal settings. They are not distinguished from managed host settings. | `scripts/codex-run.mjs` (`VERIFY_COMMAND_REQUIRED`), `scripts/config.mjs`, `hooks/config-layers.mjs` |
| CI | PARTIALLY IMPLEMENTED | The lint job checks syntax (`node --check` on every tracked `.mjs` and `.js` file), runs ESLint (`@eslint/js` recommended) and checks generated-rule drift (`sync-rules.mjs --check`); `.github/workflows/codeql.yml` adds CodeQL scanning. Required-check settings have no evidence in the workflow. [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) | `.github/workflows/test.yml`, `scripts/ci-evidence.mjs` (reports required checks as `UNKNOWN` without a token) |
| Comparative benchmarks | PARTIALLY IMPLEMENTED | No controlled native-versus-baseline-versus-Execution-v2 trial has run, so the routing overhead is unproven. | `tests/e2e/bench.mjs`, [controlled comparison](../benchmarks/execution-v2-comparison.md) (pilot 0/8, formal 0/102) |
